# SIPL conformance suite

Набір програм SIPL з очікуваним AST, кінцевим станом та помилками. Ним можна перевірити
будь-яку реалізацію SIPL, а не лише цю: `run.py` нічого не імпортує з пакета `sipl`,
а спілкується з реалізацією як із зовнішньою командою.

```
python conformance/run.py                    # еталонна реалізація (python -m sipl)
python conformance/run.py -v                 # показати кожен тест
python conformance/run.py --impl "my-sipl"   # інша реалізація
```

Код завершення: `0` — усі тести пройдено, `1` — є розбіжності, `2` — тестів не знайдено.

## Що має вміти реалізація

Дві команди, що друкують JSON-об'єкт у stdout (код завершення runner не перевіряє):

| Виклик | Обов'язкові поля відповіді |
| --- | --- |
| `IMPL parse --json ФАЙЛ` | `ok`, `ast` (якщо `ok`), `diagnostics` |
| `IMPL run --json ФАЙЛ [-s X=N ...] [--max-steps N]` | `status`, `final_state`, `diagnostics` |

- `ast` — вкладені об'єкти з полем `type`; формат вузлів описано в `docs/json-schema.md`.
  Поля `span` під час порівняння ігноруються.
- `status` — `ok`, `runtime_error` або `step_limit`.
- `diagnostics[0]` має містити `kind` (`syntax`, `runtime`, `step_limit`)
  та `span.start.line` / `span.start.column` (нумерація з 1).

## Формат тесту

Тест — це пара файлів у `cases/`: програма `ІМ'Я.sipl` та опис `ІМ'Я.json`.
Кілька описів можуть посилатися на одну програму через поле `source`.

```json
{
  "description": "Максимум двох чисел",
  "source": "max.sipl",
  "input_state": {"A": 3, "B": 7},
  "max_steps": 10000,
  "expect": {
    "syntax": "ok",
    "ast": {"type": "Program", "body": {"type": "If", "...": "..."}},
    "status": "ok",
    "final_state": {"A": 3, "B": 7, "M": 7}
  }
}
```

| Поле | Обов'язкове | Зміст |
| --- | --- | --- |
| `description` | ні | що перевіряє тест |
| `source` | ні | файл програми; типово `ІМ'Я.sipl` |
| `input_state` | ні | початковий стан; типово порожній |
| `max_steps` | ні | ліміт кроків для цього тесту |
| `expect.syntax` | так | `ok` або `error` |
| `expect.ast` | ні | очікуване AST без `span` |
| `expect.status` | ні | якщо є — програма виконується і статус звіряється |
| `expect.final_state` | ні | повний кінцевий стан |
| `expect.error` | ні | `kind`, `line`, `column` першої діагностики; кожне поле необов'язкове |

Якщо `expect.syntax` дорівнює `error`, програма лише розбирається і не виконується.

## Склад набору

- `*.json` без префікса — коректні програми: AST (для частини тестів) і кінцевий стан.
- `err_*.json` — синтаксично некоректні програми: позиція першої помилки.
- `rt_*.json` — помилки виконання: змінна без значення, ліміт кроків, строге `∨`.

## Як додати тест

1. Покласти програму в `cases/ІМ'Я.sipl`.
2. Написати `cases/ІМ'Я.json` з очікуваннями, обчисленими вручну.
3. Запустити `python conformance/run.py -v`.
