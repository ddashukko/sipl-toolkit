# Командний рядок `sipl`

```
sipl КОМАНДА ФАЙЛ [параметри]
python -m sipl КОМАНДА ФАЙЛ [параметри]    # те саме без встановленого скрипта
```

`ФАЙЛ` — шлях до програми або `-` для читання зі stdin. Файли читаються в UTF-8.

## Команди

| Команда | Що робить | Параметри |
| --- | --- | --- |
| `check` | перевіряє синтаксис | `--json` |
| `parse` | друкує AST | `--json` |
| `run` | виконує програму, друкує кінцевий стан | `-s`, `--max-steps`, `--json` |
| `trace` | виконує програму, друкує події виконання | `-s`, `--max-steps`, `--json` |
| `tree` | експортує дерево виводу або AST | `--kind`, `--format`, `-o` |
| `compare` | будує HTML-сторінку Parse Tree ↔ AST | `-o` |

## Параметри

| Параметр | Опис |
| --- | --- |
| `-s X=N`, `--set X=N` | початкове значення змінної; можна повторювати або писати `X=1,Y=2` |
| `--max-steps N` | ліміт кроків виконання, типово 10000 |
| `--json` | структурований вивід у stdout, див. [json-schema.md](json-schema.md) |
| `--kind parse\|ast` | яке дерево експортувати, типово `parse` |
| `--format text\|json\|dot\|svg` | формат дерева, типово `text` |
| `-o ФАЙЛ` | записати результат у файл замість stdout |

Крок виконання — одне присвоювання, один `skip` або одна перевірка умови.

## Коди завершення

| Код | Значення |
| --- | --- |
| 0 | успіх |
| 1 | синтаксична помилка в програмі |
| 2 | неправильний виклик або файл не читається |
| 3 | помилка виконання: змінна без значення |
| 4 | перевищено ліміт кроків |

Коди є частиною контракту й не змінюються в межах `schema_version` 1.

## Куди що друкується

- Текстовий режим: результат — у stdout, діагностика — у stderr.
- JSON-режим: один JSON-об'єкт у stdout, зокрема й у разі помилки; stderr порожній.

## Приклади

```
$ sipl run examples/valid/gcd.sipl -s A=48,B=18
Кінцевий стан: {A = 6, B = 6}
Кроків: 13

$ sipl trace examples/valid/max.sipl -s A=3,B=7
[   0] 3:3    If      if A > B then M := A else M := B
              умова A > B → false
[   1] 3:29   Assign  M := B
              M: ⊥ → 7
Кінцевий стан: {A = 3, B = 7, M = 7}
Кроків: 2

$ sipl run examples/valid/power.sipl -s X=2
examples/valid/power.sipl:4:9: error[E101]: Змінна 'Y' не має значення в поточному стані
   4 |   while Y > 0 do
     |         ^
  підказка: задайте початкове значення: -s Y=<число>
Стан на момент зупинки: {R = 1, X = 2}
Кроків: 2

$ echo "begin while 1 = 1 do skip end" | sipl run - --max-steps 100
<stdin>:1:13: error[E102]: Перевищено ліміт кроків (100); можливо, цикл нескінченний
...
```

У текстовому trace число в дужках — кількість кроків, виконаних до початку оператора; `⊥` означає,
що змінна ще не мала значення.

## Візуалізація

```
sipl tree prog.sipl                          # дерево виводу в нотації практикуму
sipl tree prog.sipl --kind ast               # AST текстом
sipl tree prog.sipl --format json            # дерево з фрагментами коду у вузлах
sipl tree prog.sipl --format dot -o t.dot    # Graphviz: dot -Tpng t.dot -o t.png
sipl tree prog.sipl --format svg -o t.svg    # SVG без сторонніх програм
sipl compare prog.sipl -o compare.html       # відкрити у браузері
```

Дерево виводу записано в нотації практикуму: вузли `<програма>`, `<оператор>`, `<вираз>`,
`<умова>`, `<змінна>`, `<число>`, листки — лексеми програми; у SVG і DOT ребра — стрілки.

На сторінці `compare.html` наведення на вузол підсвічує його фрагмент коду й вузли іншого дерева,
що відповідають тому самому фрагменту; клік закріплює вибір.
